## 1. COMMAND概述

### 1.1 用途定义

omt:tune是OMT系统中用于**在任何阶段对单个artifact进行精细化调整**的COMMAND。它提供了一种轻量级、低侵入性的修改机制，允许用户在不触发完整Phase重置的情况下，对已创建的artifact进行局部优化。

### 1.2 核心能力

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           omt:tune 核心能力矩阵                               │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐         │
│  │  单文件读取      │───▶│  精准修改       │───▶│  联动对齐检查   │         │
│  │                 │    │                 │    │                 │         │
│  │  - @path解析    │    │  - 局部调整     │    │  - align-part   │         │
│  │  - 类型识别     │    │  - 结构保持     │    │  - 一致性检查   │         │
│  │  - 内容加载     │    │  - 增量变更     │    │  - 影响报告     │         │
│  └─────────────────┘    └─────────────────┘    └─────────────────┘         │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 1.3 与omt:*-new系列的配合

omt:tune与omt:*-new系列形成**创建-检查-调整**的闭环工作流：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│  omt:*-new 创建 ───▶ 用户检查 ───▶ 发现问题 ───▶ omt:tune 调整             │
│       │                     │                       │                      │
│       ▼                     ▼                       ▼                      │
│  artifact生成          review结果              调整后artifact              │
│  (draft状态)           (接受/拒绝)             (重新对齐)                   │
│                                                                             │
│                           继续omt:*-new创建下一个                           │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 2. 输入参数定义

### 2.1 TypeScript接口

```typescript
/**
 * omt:tune COMMAND输入参数
 */
interface TuneInput {
  /**
   * 目标artifact路径
   * 格式: @<artifact_path>
   * 示例: @tspec_001/proposal.md
   */
  target: string;

  /**
   * 用户调整反馈内容
   * 包含调整意见、修改建议、问题描述等
   */
  feedback: string;

  /**
   * 调整模式
   * - 'single': 只调整目标文件，不级联
   * - 'cascade': 级联调整相关依赖文件
   * 默认: 'single'
   */
  mode: 'single' | 'cascade';
}

/**
 * omt:tune COMMAND执行结果
 */
interface TuneResult {
  /**
   * 执行状态
   */
  status: 'success' | 'failed' | 'pending';

  /**
   * 调整后的artifact内容
   */
  adjustedContent: string;

  /**
   * 调整记录ID
   */
  tuneId: string;

  /**
   * 对齐检查结果
   */
  alignmentResult: AlignmentCheckResult;

  /**
   * 影响范围（cascade模式）
   */
  affectedChain?: string[];

  /**
   * 用户确认提示
   */
  confirmationPrompt: string;
}

/**
 * 对齐检查结果
 */
interface AlignmentCheckResult {
  /**
   * 对齐状态
   */
  status: 'aligned' | 'misaligned' | 'warning';

  /**
   * 一致性问题列表
   */
  issues: AlignmentIssue[];

  /**
   * 建议修复项
   */
  recommendations: string[];
}

/**
 * 一致性问题定义
 */
interface AlignmentIssue {
  /**
   * 问题类型
   */
  type: 'dependency' | 'reference' | 'structure' | 'content';

  /**
   * 问题描述
   */
  description: string;

  /**
   * 相关artifact路径
   */
  relatedArtifact?: string;

  /**
   * 严重程度
   */
  severity: 'high' | 'medium' | 'low';
}
```

## 4. 轻量历史记录设计

### 4.1 记录文件格式

```
.omt/tune/tune_<id>.yaml
```

### 4.2 YAML结构

```yaml
# Tune历史记录 - 轻量设计
id: tune_20260501_001
timestamp: 2026-05-01T10:30:00Z

# 目标artifact信息
target:
  path: tspec_001/proposal.md
  type: TSpec

# 用户反馈（原文）
feedback: "第三点设计不合理，建议改为..."

# 变更类型标记
change_type: MODIFIED  # CREATED | MODIFIED | DELETED | RESTRUCTURED

# 调整模式
mode: single

# 影响范围（cascade模式时记录）
affected_chain: []

# 对齐检查结果
alignment_status: aligned

# 决策信息
decision:
  accepted: true
  user_action: confirmed
  follow_up: none
```

### 4.3 设计原则

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          轻量历史记录设计原则                                 │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  原则1: 不存储修改后的完整内容                                        │   │
│  │      - 原因: artifact文件本身已包含最新内容                            │   │
│  │      - 策略: 只记录变更类型和位置                                      │   │
│  │      - 好处: 减少存储开销，避免冗余                                    │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  原则2: 只记录决策信息                                                │   │
│  │      - 用户反馈原文                                                   │   │
│  │      - 变更类型标记                                                   │   │
│  │      - 用户决策（接受/拒绝）                                           │   │
│  │      - 后续行动                                                       │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  原则3: 用于回滚和审计追踪                                            │   │
│  │      - 支持按tuneId回滚                                               │   │
│  │      - 提供审计追踪链                                                  │   │
│  │      - 便于问题定位                                                   │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

| Tune调整类型 | Alignment结果 | 用户决策 | 后续行动 |
|-------------|--------------|---------|---------|
| single + 局部 | aligned | 接受 | 继续正常流程 |
| single + 局部 | misaligned | 接受 | 记录问题，用户后续处理 |
| single + 局部 | misaligned | 拒绝 | 回滚调整 |

## 9. TypeScript接口汇总

### 9.1 完整接口定义

```typescript
/**
 * omt:tune COMMAND完整接口汇总
 */

// ============ 输入输出接口 ============

interface TuneInput {
  target: string;
  feedback: string;
  mode: 'single' | 'cascade';
}

interface TuneResult {
  status: 'success' | 'failed' | 'pending';
  adjustedContent: string;
  tuneId: string;
  alignmentResult: AlignmentCheckResult;
  affectedChain?: string[];
  confirmationPrompt: string;
}

// ============ 对齐检查接口 ============

interface AlignmentCheckResult {
  status: 'aligned' | 'misaligned' | 'warning';
  issues: AlignmentIssue[];
  recommendations: string[];
}

interface AlignmentIssue {
  type: 'dependency' | 'reference' | 'structure' | 'content';
  description: string;
  relatedArtifact?: string;
  severity: 'high' | 'medium' | 'low';
}

// ============ 历史记录接口 ============

interface TuneHistoryRecord {
  id: string;
  timestamp: string;
  target: {
    path: string;
    type: 'TSpec' | 'MSpec' | 'Sprint' | 'AtomTask';
  };
  feedback: string;
  change_type: 'CREATED' | 'MODIFIED' | 'DELETED' | 'RESTRUCTURED';
  mode: 'single' | 'cascade';
  affected_chain: string[];
  alignment_status: 'aligned' | 'misaligned' | 'warning';
  decision: {
    accepted: boolean;
    user_action: 'confirmed' | 'rejected' | 'modified';
    follow_up: string | null;
  };
}

// ============ 执行器接口 ============

interface TuneExecutor {
  /**
   * 执行tune调整
   */
  execute(input: TuneInput): Promise<TuneResult>;

  /**
   * 解析目标artifact
   */
  parseTarget(target: string): Promise<ArtifactInfo>;

  /**
   * 分析调整反馈
   */
  analyzeFeedback(feedback: string, content: string): AdjustAnalysis;

  /**
   * 执行调整
   */
  performAdjust(
    content: string,
    analysis: AdjustAnalysis,
    mode: 'single' | 'cascade'
  ): Promise<string>;

  /**
   * 触发对齐检查
   */
  triggerAlignment(tuneId: string): Promise<AlignmentCheckResult>;

  /**
   * 记录历史
   */
  recordHistory(record: TuneHistoryRecord): void;

  /**
   * 回滚调整
   */
  rollback(tuneId: string): Promise<void>;
}

interface ArtifactInfo {
  path: string;
  type: 'TSpec' | 'MSpec' | 'Sprint' | 'AtomTask';
  content: string;
  structure: Record<string, unknown>;
}

interface AdjustAnalysis {
  scope: 'single_point' | 'multi_point' | 'global';
  intent: string;
  needsCascade: boolean;
  affectedArtifacts: string[];
}
```

## 11. 总结

omt:tune COMMAND作为OMT系统的精细化调整机制，具有以下核心特点：

### 11.1 设计要点

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          omt:tune 设计要点总结                               │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  1. 轻量调整机制                                                            │
│     - 单文件读取 + 精准修改                                                 │
│     - 不触发Phase重置                                                       │
│     - 增量变更，保持结构                                                    │
│                                                                             │
│  2. 双模式支持                                                              │
│     - single: 单文件调整                                                    │
│     - cascade: 级联调整                                                     │
│                                                                             │
│  3. 自动对齐检查                                                            │
│     - tune后自动触发align-part                                              │
│     - 检查依赖/结构/内容一致性                                               │
│                                                                             │
│  4. 轻量历史记录                                                            │
│     - 只记录决策信息                                                        │
│     - 不存储完整内容                                                        │
│     - 支持回滚和审计                                                        │
│                                                                             │
│  5. 与*-new闭环配合                                                         │
│     - 创建-检查-调整循环                                                    │
│     - 分步artifact创建                                                      │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 11.2 与其他COMMAND的关系

| COMMAND | 关系 | 说明 |
|---------|------|------|
| omt:*-new | 配合 | tune调整*-new创建的artifact |
| omt:align-part | 联动 | tune后自动触发 |
| omt:terminator | 子COMMAND | terminator模式下的调整工具 |
| omt:checkpoint | 记录 | tune历史作为checkpoint的一部分 |
